# AnyID 原生文本编码设备与吞吐实验

## 目标与单因素边界

此前8条AnyID preview over Wan2.2 TI2V-5B的生成计时中位525.956秒，20步DiT日志约12–13秒；差额不是已经测量的T5耗时。固定上游支持原生GPU T5路径：先在GPU编码正负文本，offload将T5回CPU，然后DiT上GPU，最终DiT回CPU、VAE解码。该路径不修改权重、文本、采样算法或扩散调度。

本轮只暴露 `parameters.t5_cpu`，默认保持True；候选设False。`offload_model=True`、BF16、已校验基础权重/合并AnyID LoRA、原crop、sample_id派生seed、原prompt、原生默认负prompt、shift3、UniPC、20steps、480²/49输出帧/16fps不变。CPU/GPU算子可产生数值微差，不承诺context或视频逐bit相同，也不将其称作训练或身份方法增益。

`TimedTextEncoder`仅委托原生编码器并记录同步墙钟，保存两次正/负文本编码耗时和context shape。`generation_seconds`包含VAE参考编码、文本编码、设备迁移、采样、解码，不含外部视频编码；`backend_elapsed_seconds`含加载与外部编码。GPU `.to()`/`.cpu()`迁移耗时不在文本调用时钟内，因此与总生成耗时分开解释。

## 冻结输入与预算

沿用上轮8条CREMA-D开发输入，不增加训练或holdout。新增一条CPU-T5控制和同输入GPU-T5 pilot，原始8条CPU结果保留；pilot媒体/数值/资源通过后GPU-T5生成其余7条，总新增8条候选。

| run | 候选数 | GPU数 | timeout | 预留GPU小时 |
|---|---:|---:|---:|---:|
| CPU-T5控制 | 1 | 1 | 900秒 | 0.25 |
| GPU-T5 pilot | 1 | 1 | 900秒 | 0.25 |
| GPU-T5剩余批次 | 7 | 1 | 5400秒 | 1.50 |
| 总计 | | | | 2.00 |

所有已启动作业需正确退出并保留失败证据；无额外生成重试槽，不因失败自动扩大预算。文本评价为本地CPU，独立墙钟上限2小时，不上传身份媒体、embedding或私人清单。

## 验收与结论门槛

- 完整媒体输出、49帧/尺寸/fps符合，生成张量有限、正负文本各调用一次，原始输入、种子、权重和上游commit对应一致。
- 先对单条CPU/GPU真实分段计时，再对8条相同输入核对生成时间、backend成本、显存与覆盖率。
- 使用已冻结SCRFD/ArcFace协议和原参考anchor评分；缺脸不补0，均值注明样本分母。描述性配对统计按演员聚合，4演员不能作泛化主张。
- GPU-T5若更快而身份/覆盖退化，则只报告执行效率变化，不升级为已验证质量改善；灰度运动不替代文本/动作/感知质量。
- 公开发布只有代码、可复用配置、锁定协议和聚合结论；内部路径、地址、凭据、真实图片与逐身份记录留在受控节点。

## 实测结果

本轮3个有限run均正常结束：新增CPU-T5控制1条、GPU-T5 pilot1条及批次7条。9条新增输出全部完整解码，均480²、49帧、16fps；两次原生正/负文本编码及设备字段已核验，原图、seed、prompt、模型和冻结评价协议对应一致。未使用额外生成重试槽。

| 指标 | CPU-T5 | GPU-T5 |
|---|---:|---:|
| 本轮同输入单条正/负文本编码合计 | 504.539秒 | 0.383秒 |
| 本轮同输入单条完整生成计时 | 525.787秒 | 31.118秒 |
| 固定8输入完整生成中位数 | 525.956秒（既有CPU批次） | 25.257秒（本轮GPU批次） |
| 8输出backend分配GPU小时，含各run加载 | 1.214463（既有CPU批次） | 0.105299 |
| 有效身份视频 | 7/8 | 7/8 |
| 8视频身份可评分帧coverage | 0.875 | 0.875 |
| 有效视频身份余弦均值 | 0.831946 | 0.849399 |

同输入CPU/GPU生成速度比为16.897；8输入中位速度比为20.824，后者包含跨run的历史CPU对照，不能当作8次独立随机重复的速度置信区间。GPU正/负文本调用计时中位0.132秒，模型迁移不包含在文本调用计时内，但计入完整生成计时。数据直接确认此前CPU BF16文本编码是主要瓶颈：本轮控制中504.539/525.787秒消耗在文本调用内。

本轮含CPU控制共0.272482GPU小时，低于2小时硬上限。GPU候选最大allocated14.599GB/reserved17.507GB，未发生OOM。上述GPU小时是声明GPU数乘backend墙钟，不是NVML利用率积分或调度器账单。

7个共同可评分视频、4演员的共同帧按演员身份均值变化为+0.015652，灰度运动proxy比1.021147。CPU/GPU BF16算子确实产生不同视频，不声称bit-exact；小样本分数变化不解释为训练或身份方法收益。缺脸问题没有解除，前后都保留1/8视频的身份缺失；缺失余弦未补0，不以高有效帧均值掩盖覆盖失败。

结论：**在本机及本轮配置下，原生GPU-T5加既有offload通过有限执行效率验收，显著减少文本编码耗时，未见本次身份覆盖退化。** 默认行为仍保持CPU-T5以免未经验证改变其他部署；经过校验的后续配置可显式设置 `t5_cpu:false`。这不是完整参赛模型的质量晋级，尚需更广身份、动作、种子、人工及holdout评价。

公开数值证据见 `resources/anyid_t5_result.json`。完整输入、逐视频评分、模型与运行哈希、媒体校验及依赖冻结在本地保存；没有将前一个目标完成记录冒充本轮run。
