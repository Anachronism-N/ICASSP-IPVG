# AnyID参考上下文：有限质量对照

## 2026-10-19预注册

最终目标是生成效果，不是吞吐。原生GPU-T5仅降低实验执行等待；本轮不将速度作为质量晋级指标。

### 诊断与唯一假设

此前AnyID的8条开发视频中1条固定8帧均无可评分脸。独立本地检查该视频全部49帧，固定SCRFD仍49/49未检出；这只是检测器失败证据，不等于确认画面中无人脸。同演员、同裁剪的另一提示有完整身份评分，不能简单归因参考不可识别。

假设：将正方形参考裁剪每侧margin从0.3增至0.6，给原生AnyID整图参考latent更多头部和周边上下文，能改善生成可评分覆盖，同时不损害身份与运动。仍用同一个`square_crop`实现，无新增参考、目标首帧、脸重建、额外生成候选或训练。原始参考永远作评价anchor。

暂不改CFG。固定上游`wan/pipeline.py`的positive使用真实参考、negative使用空参考latent，CFG同时耦合文本与参考强度，不是独立文本旋钮。负prompt参数空字符串会回退原生默认负prompt，本轮保持不变。480²采用原已验证shift3、UniPC20steps、CFG5、49帧16fps、单候选和`t5_cpu:false`。

### 数据、种子和配对

- 使用CREMA-D已冻结dev，绝不消费train、holdout或竞赛test媒体。
- 4名已有诊断演员、每演员2个原prompt；再从剩余dev按`SHA256('anyid-context-v1:'+identity_id)`排序选8名，每名2prompt。额外dev演员不是正式独立holdout。
- 每输入seed offset42与43，保持原`sample_id`，实际seed仍是offset加sample_id哈希模2³¹。新增逐行`generation_seed`，只用于同输入跨种子对照，默认行为不变。
- 两condition各48条，总96。旧失败样本seed42每condition各1条作工程pilot；主批其余94条。
- 两节点独立单GPU，按演员分成两shard；同演员两condition固定在同节点同物理GPU，以免硬件和研究因素混淆。旧诊断组与8新dev演员分别报告；不按生成结果更换演员或追加种子。

### 冻结评价与研究门槛

身份继续用`arcface_cremad_v1`及既有ONNX哈希/原anchor：8帧均匀采样、单脸五点对齐、missing省略相似度、coverage另报。生成因素与评价协议不混改。

主门槛为完整输出96/96，以及新dev组和全量组的身份可评分coverage均提高；新dev至少7/8有效帧的视频数不能下降。共同至少7帧的视频按演员聚合，身份均值delta不得低于-0.02，P10 delta不得低于-0.02。主批结果分析前追加最低配对演员覆盖保护：全量至少10/12演员、新dev至少6/8演员有共同有效配对，避免只剩少数容易演员时认定非劣；这是显式方案补充，不是原身份协议变化。每seed单独报告coverage，不能让单seed收益掩盖另一seed恶化超过0.05。

运动退化保护：按全样本灰度运动proxy均值比至少0.8，静态比例（灰度差<0.5）增量不超过0.10。此代理不能证明说话、微笑、动作语义、运动自然性或感知质量；没有完成本地语义评价或人工盲评，就只能称局部身份/coverage开发候选，不是最终base或完整效果验收。旧失败pilot恢复只是诊断，不够晋级。负结果同样发布，不搜索多种margin。

### 资源、工程验收与停止

总最坏声明4 GPU小时：2个pilot各900秒共0.5；8个主batch各1350秒共3；唯一工程修复槽1800秒共0.5。所有run单GPU、有新ID、超时、源码/配置/manifest/模型hash与实际allocation墙钟台账。工程pilot检查shape、finite、完整解码、seed和原anchor元数据，不根据pilot身份分决定是否运行剩余固定样本。

任一工程失败先停止后续启动并诊断；保留失败，最多使用一个修复槽，不因质量负结果重试。CPU准备/评价各设置独立有限墙钟，不进入GPU模型生成成本。两节点历史异常卡排除，实际launch前核对空闲，无跨节点DDP。

## 独立文本代理补充（生成因素与身份协议不变）

本地找到OpenAI CLIP ViT-B/32 JIT权重，353,976,522字节，SHA256 `40d365715913c9da98579312b702a82c18be219cc2a73407c4526f58eba950af`，与已安装官方CLIP模型注册表中的预期hash一致。不下载，不使用其他项目微调权重。`clip_text_eval.py`只接该本地文件；CPU FP32/4线程、官方全帧preprocess、固定8帧、精确原prompt且拒绝77token超长截断、单位化image/text余弦均值、不乘logit_scale。独立协议`clip_b32_frame_text_v1`对两condition一致重评，不修改ArcFace协议。

先对真实源dev视频检查neutral/happy提示辨别力：64源视频中匹配prompt余弦高于另一prompt的比例为53.125%，contrast均值0.007626，不足以承担动作/表情语义验收。仍对生成输出报告同输入均值差和两原prompt余弦差作为辅助诊断。若真实源的prompt contrast辨别不足，明确标为不适合作语义验收；不按生成结果调text模板或阈值。CLIP单帧不能证明说话或动作顺序，也受构图与背景干扰；结果仅为辅助诊断，不改变已冻结的身份/coverage研究门槛。

## 复现入口

先用`prepare_reference_crop.py --margin 0.6`从原manifest创建全新dev条件目录，复用既有0.3条件。`prepare_anyid_context.py`检查原dev/legacy/两条件的prompt、actor、reference/source/hash并产生固定96条分片清单。发布版本显式通过`--pilot-sample`传入本地冻结协议中的诊断输入ID，避免在公开源码中硬编码真实媒体标识；原实验清单与产物保留不覆盖。上游AnyID、LoRA和底座版本沿用`resources/two_track_models.lock.json`，不修改源权重。CPU回归及真实GPU运行结果在后续完成后追加，预注册不提前写成功。

公共仓库只发布薄脚本、测试、方案和聚合结果，不含真实媒体、逐演员清单、embedding、内部节点、账号或凭据。

## 诊断pilot（不单独作晋级结论）

两条件各1条均完成并通过49帧/480²/16fps完整解码及实际seed验收。窄参考输出与此前GPU-T5相同样本hash一致，仍0/8可评分；宽上下文恢复8/8可评分，原anchor余弦均值0.864936、P10为0.838837。该样本灰度运动11.821379→5.795228，有运动幅度下降；不能因为缺脸恢复就宣称完整生成质量改善。两pilot实际0.060485GPU小时，完整96条固定实验与多维审计完成后再作结论。

最终完整视觉环境244项CPU测试通过，干净环境101项通过/15项可选依赖跳过，CPU烟测通过。公开配对入口重算的五组点估计、恢复/丢失和排序演员bootstrap与独立审计一致。两只读辅助代理遭遇499服务取消，主流程直接读取固定上游并完成关键诊断；不把未完成代理输出当完整验证。

10/10run及96/96输出正常完成、完整49帧解码、480²/16fps校验；模型/source/hash、prompt、原anchor和实际seed核验通过。总backend0.910532GPU小时≤4，无工程修复重试。两节点生成结束后无遗留GPU任务。
