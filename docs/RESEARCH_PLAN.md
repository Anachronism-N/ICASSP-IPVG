# 研究问题、对照与评价协议

研究主线是：**在固定生成预算下，按失败原因分配身份与动作修正，能否比单次生成、固定重采样和统一修正更可靠？** 这是待验证的问题，不是已证实的新方法。视频 agent、自我批评和关键帧修正已经有相关工作；创新要由明确的方法区别、同预算比较和消融证明。

Track 1 优先形成完整证据。Track 2 另研究主体/事件状态约束如何改善多动作时间对齐。结构化时间线或场景状态不自动证明系统学到了可泛化世界模型。

## 三个递进假设

| 假设 | 最小改动 | 主要验证 | 反例与淘汰条件 |
|---|---|---|---|
| H1：身份参考条件的质量/强度可改善运动中的身份保持 | 固定基座，仅调参考裁剪/身份条件强度或一个可训练身份模块 | 脸可见帧身份相似度、身份漂移、文本符合、有效运动 | 分数提高来自静态正脸或动作减少，淘汰 |
| H2：按错误类型选择修正动作比均匀追加生成更高效 | 固定候选模型，分别处理身份漂移、动作缺失、时间错位和坏片 | 同 GPU 时间/同候选上限下的多维 Pareto 改进 | 仅靠更多采样/更大模型获益，不能归因调度策略 |
| H3：Track 2 的事件状态与局部时间条件减少动作遗漏/乱序 | 固定主体条件，增加显式事件边界与时间段条件 | 动作覆盖、顺序、边界误差、主体一致、转场连续 | 全局动作正确但时点不准；拼接导致身份/视觉断裂 |

H1 先通过再做 H2；H3 不以未公开的 ReactID 代码为前提。对源论文思想的独立实现要明确标注来源，不能声称官方复现完成。

## 数据隔离与开发集合

最小记录包括 sample ID、track、主体/身份组 ID、source video ID、参考图、目标视频/prompt、事件时间线、来源与许可、文件校验和。禁止用随机行划分替代身份隔离。

划分采用身份和源视频的**连通分组**：只要两条记录共享身份或源视频，即属于同一不可拆分组；对于近重复、裁剪版本或重编码再加重复组。再对整组分配 train/dev/locked-test。如此避免同一视频的多个主体或同一身份的不同视频跨集合泄漏。缺少稳定身份/源视频信息的记录不能假称已隔离，应补齐或单独隔离不用来估计泛化。

建议阶段规模：

- smoke：约 32 对，用于可运行性和坏片检查，不用来宣称泛化。
- dev-small：约 128 对，供有限自动搜索；覆盖近景/远景、转头/遮挡、单/多人、静/动背景和长动作。
- dev-full：根据产能扩大到 256—512 对，保留相同分组原则和场景覆盖。
- locked-test：至少约 128 对独立身份/源视频；只在预先定义的阶段门槛使用，不能每轮查看后继续调参。

这些是执行建议，不是官方划分。优先保证身份多样性，置信区间按身份或连通组 bootstrap，不能把相关帧当独立样本。官方最终测试集不进入任何训练/搜索循环。

## 评价器的锁定

本届公开规则只给评价维度，完整公式与权重尚未核实。所有本地数值都称 **proxy**。正式提交前若官方发布 scorer，用明确的新协议版本对已冻结候选重新评价，不覆盖旧结果。

在首轮真正比较前锁定：输入清单 hash、解码/抽帧、脸检测器与身份编码器 revision、文本/动作评价器、分辨率和时间轴换算、缺失检测的处理、各项阈值、聚合方法和评价代码 commit。agent 不得一边改模型，一边改主评价器来证明收益。

| 维度 | 建议测量与限制 | 必须同时报告 |
|---|---|---|
| 身份 | 脸检测后与参考特征相似；分段/低分位数测漂移；人脸编码器仅适用于人脸 | 检出率、可评分帧比例、最差分段、遮挡/远景子组；缺脸不能静默丢弃 |
| 一般主体 | 对动物/物体采用合适的视觉特征与区域对齐 | 主体类型分组；不能把无脸主体的人脸分数填零或假定高分 |
| 文本/动作 | 文本—视频特征或本地多模态判断；按原子动作分解 | 每动作完成率、遗漏率、人工抽查，避免只看全局相似度 |
| 时间线 | 对事件窗口评价动作是否发生、顺序与边界偏差 | 每事件得分、窗口长度和换算规则；全局 caption 正确不等于时点正确 |
| 连续/运动 | 画面连续、合理位移/姿态变化、运动有效性 | 静止率、闪烁、镜头突变、动作量与身份分数的权衡 |
| 可用性 | 视频存在、可解码、帧数/fps/尺寸/长度符合配置 | 缺失/损坏比例，坏片计入总体覆盖率 |
| 成本 | GPU 秒、型号/数量、显存、候选数、采样步、API tokens/费用 | 训练、生成、评价、失败重跑分别计账 |

无真实视频或无可用模型时，只能跑结构/合成指标 smoke；合成数据分数不参与真实模型晋级。真实评价缺失的指标必须显式标缺失，不能用默认零/随机分数充当真实结果。

## 预算公平的对照

每次比较选一个主要预算口径并同时报告其余口径。建议主要约束为“每输入对实际 GPU 秒上限 + 候选数硬上限”；固定同样的分辨率、帧数、采样步数、参考图与输入信息。不同模型速度不同，候选数相等不代表成本相等。

| ID | 系统 | 目的 |
|---|---|---|
| B0 | 固定基座、原始 prompt、单次生成 | 最基本可重复参考 |
| B1 | 同一模型、固定 K 候选、预先固定 proxy rerank | 隔离单纯重采样收益 |
| B2 | 所有样本统一追加同类修正 | 隔离“有修正”本身的收益 |
| M1 | 失败分类 → 对应修正，预算封顶 | 测试选择性策略 |
| O1 | 离线 oracle 选候选（仅分析） | 估计候选池上限；不当可部署方法或正式提交策略 |

best-of-N、prompt 改写、编辑与后处理的正式比赛许可尚待主办核准；本地研究对照不代表这些操作已获参赛授权。oracle 不得使用官方隐藏标签；独立人工/离线分析结果清楚区分。

## 单因素消融计划

每行从指定 parent 仅改变一个因素。基座、数据 split、proxy、预算和其他超参数必须相同。不要把全部组合直接笛卡尔积扩成数百个任务。

| ID | Parent | 唯一变化 | 预期机制 | 必须检查 |
|---|---|---|---|---|
| A01 | B0 | 参考图裁剪/对齐策略 | 去除背景干扰，保留脸/主体信息 | 远景与侧脸是否退化；未增加额外参考 |
| A02 | B0 | 身份条件强度一档 | 身份与动作的权衡 | 动作量、文本分数和静止率 |
| A03 | B0 | 高质量训练子集过滤 | 减少错配和坏脸 | 相同样本数/步数对照，避免只因多数据 |
| A04 | B0 | 身份模块/LoRA 一个训练版本 | 学到可泛化身份绑定 | 独立身份 dev；梯度与导出回载一致 |
| A05 | B1 | 加入失败分类，候选预算不变 | 有针对性地分配候选 | 总 GPU 秒、错误分类准确度 |
| A06 | M1 | 去掉失败类型，只保留二值失败 | 测试类型信息是否有用 | 同阈值/同修正预算 |
| A07 | M1 | 去掉局部修正，用整段重生成 | 测试局部处理 | 质量、身份、时间与成本一起比较 |
| A08 | Track2 B0 | 只加事件文本规划 | 测试结构化 prompt 的效果 | 不把文本重写当模型训练收益 |
| A09 | A08 | 加局部时间条件/窗口机制 | 测试时间绑定机制 | 动作边界、转场与主体连续 |
| A10 | A09 | 去掉持久主体/事件状态 | 测试状态约束贡献 | 长时遗忘、事件重复/遗漏 |

LoRA rank、学习率、帧数、分辨率与数据规模属于工程/容量选择，单独记录；不和核心方法消融混为一张表。候选晋级需保存失败实验，防止 agent 反复提出已无效的配置。

## 晋级门槛与人工盲查

建议在运行前写入 promotion policy：所有样本覆盖且指标完整；关键质量/动作指标不得超过预设容忍度退化；身份/主目标提升在相同预算下稳定；至少 2—3 个种子或独立复跑能解释波动。阈值可在 pilot 确定，但冻结后不能为了保留某候选临时下调。

每个主要候选随机盲查约 30—50 对，覆盖难例，隐藏方法名并打乱顺序。比较身份、动作、时间、自然度和总体偏好；记录分歧与失败类别。不以单个 VLM 评分作为唯一真值，也不只展示最好视频。

locked-test 仅用于阶段验收。若结果不佳，记录为失败并返回新一轮开发；之后对同一 locked-test 的结果不再当独立无偏证明。可另建新的独立组，但不得删掉之前的失败记录。

## 论文证据清单

- 明确的问题、和 ReactID/KeyID/IPVG-STD/AESR/VISTA 等既有方法的区别。
- 同输入信息、同预算、同评价版本的完整对照和单因素消融。
- 多身份/多源视频泛化、难例子组、成本与不确定性。
- 训练、推理、数据清单、模型和代码版本以及失败实验。
- 人工评价方法、样本选择、标注方式及统计口径。
- 正式测试的允许操作和最终出版 track 的确认材料。

ICASSP/IPVG 的参赛报告不自动等于 CCF B Full/Regular；以最终出版类别与所在单位认定为准。这里不承诺创新性或录用。
