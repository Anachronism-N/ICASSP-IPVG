# 相关工作与 ITA 视频模型迁移方案

核查日期：2026-10-20。硬件为2节点、每节点8张A100 40GB。本文将可复现基线、方法参考和待验证设计分开；没有新增GPU实验或实现私有模型适配。ITA在本文暂指图像Image、文本Text、音频Audio共同输入，直接输出RGB视频；若原模型定义不同，需要相应调整。

## 沿用的训练资源与不同的测试任务

MM2026与ICASSP2027的Track 1均指向VIP-200K，支持复用数据解析、参考图预处理和身份条件方法。但不能据此认定隐藏测试相同：MM2026正式测试页为200个案例，每例一份参考图与prompt；ICASSP2027页面写200个身份、每身份5条prompt，共1000对。不得把旧测试清单的数量、文件命名、格式和评测结果直接套到本届。[MM2026官方页面源码](https://github.com/HiDream-ai/ipvg-challenge-2026.github.io/blob/main/index.html)、[ICASSP2027官网](https://hidream-ai.github.io/ipvg-challenge-2027.github.io/)

旧测试可作为历史复现与工程回归材料；若使用了在旧测试域调整过的prompt、playbook或参数，它就不能再充当独立无偏holdout。新项目仍要从训练资源中按身份/源视频独立划分开发与保留验收集。外部模型、重采样、编辑和测试时适配是否准用于2027正式提交，须按本届规则确认。

原始入口：[AESR](https://github.com/oceanflowlab/AESR)、[AESR论文](https://arxiv.org/abs/2608.20749)、[KeyID](https://github.com/WISLab-GDUT/KeyID)、[IPVG STD](https://github.com/rain152/IPVG)。以上方案说明提示、身份锚点、编辑和候选选择具有实际价值；不能仅因它们未训练新视频模型，就忽略它们作为强对照的必要性。[TPIGE公开实现](https://github.com/Andyplus1/IPT2V)的revision74390b4b具有真实Apache-2.0 LICENSE.txt，与仅README宣称许可的仓库分开。

AESR已公开evaluation/README中的候选自动权重：`.15*(GME+Story)+.20*(Cur+Arc)+.15*(Motion+Imaging)`，并明确此式不能复现主办人工组件。这更新了此前只读论文中“权重未提供”的证据边界：论文未给数值，而作者eval文档给了选片权重。它不是官方FinalScore。VBenchAMT/MUSIQ现已在本项目同protocol真实执行；缺CurricularFace/GME/Story和人工不补0、不重归一化，不把我们的ArcFace/CLIP设置直接等同作者未锁的face/text实现。详情见[共同评测与选锚实验](EXPERIMENT_MM2026_KEYFRAMES.md)。

评测门槛解除后的顺序：任务专用推理基线与现有VACE工程基线在相同输入/预算下比较→固定基座→从身份/动作条件平衡或一个可训练模块开始→再加失败类型驱动的有限修正。只有在训练收益、帧率/分辨率与成本都能解释时扩大数据和模型。直接延续往届方法可以形成参赛起点，独立论文仍需明确改进和消融。

## 从 ITA 到 Track 2 的核心差别

建议保留“直接视频生成”的路线，不因任务转换就强行改成骨骼生成再渲染。可尝试复用图像条件、视频骨干、跨帧连续性、训练工程以及原模型确实具备的时间对齐能力；具体可复用模块取决于代码和权重，不能仅根据ITA输入接口推断其内部有某种RoPE或cross-attention。

| ITA中的条件或能力 | Track 2对应条件 | 需要新增或核查 |
|---|---|---|
| 参考人物图像 | 全程持续的主体身份参考 | 图像条件是否仅锁首帧；侧身/遮挡后是否漂移 |
| 全局舞蹈/风格文本 | 全局场景及动作目标 | 能否控制非舞蹈动作、物体交互、位移与镜头 |
| 音频节奏/时变特征 | 每段动作文本、开始/结束时间与段内相位 | 节奏同步不等于动作语义或时间窗口完成，需要事件条件训练 |
| 长片段连续生成 | 多动作之间的过渡 | 前一事件状态、动作完成、边界衔接与后续身份保持 |
| 节拍/舞蹈评价 | 身份、逐事件动作、顺序、起止误差和视频质量 | beat指标不能替代本届时间线评价 |

Track 2不提供音乐输入。不能把音频静音当作已完成无音频适配：静音波形经过编码器的特征通常不等于原模型的null/unconditional条件，应检查CFG及condition dropout实现，在训练中覆盖真实缺失音频分布。不得通过测试时输入不存在的真实音乐或目标动作视频来补足条件。[任务原文](https://hidream-ai.github.io/ipvg-challenge-2027.github.io/)

## 最小改造设计

以下为待验证建议，不是已经实现的方法。

1. 保留参考图像与全局文本；对同一输入分别测试真实音乐、静音音乐、模型正确null音频路径，诊断音频依赖。如果模型本身没有无音频能力，先训练condition dropout或null条件适配，区分“去掉音乐”的退化与“时间控制”的收益。
2. 把每个事件编码为“动作文本、开始时间、结束时间”；结合真实输出帧率、VAE时间压缩和参考帧前缀，映射到视频latent时间位置。不能直接把第t帧当第t个latent token；视频物理时间与扩散噪声timestep也不是同一变量。
3. 新增小型事件/时间适配器，用分段条件注入或局部attention将每段动作绑定到对应时间窗口；边界使用可控重叠/软过渡，并保留持续的全局文本与身份条件。文本embedding不应未经投影直接冒充音频特征。
4. 首轮冻结大部分视频骨干，只训练新条件模块或选定LoRA。仅在动作能完成但身份漂移时再加入专门身份约束；避免同时更换全部条件、骨干和loss。
5. 从ReactID已授权的人类主体片段做最小实验，训练不只包含舞蹈。对动物/物体另设通用主体生成基线与评价；人体模型不应强行处理全部类别，也不能在正式提交时漏掉非人样本。

候选推理流程：参考图I + 全局文本T + 动作事件及时间 → 身份/全局条件 + 局部事件条件 → 视频生成骨干 → 完整视频 → 逐事件评价与有限修正。音频分支只有在明确辅助训练或可选输入条件下使用，最终系统须能处理比赛实际提供的输入。

## 最小实验与决策门槛

| 实验 | 唯一关键变化 | 用于回答 |
|---|---|---|
| M0 | 原ITA模型使用其正确null音频路径、全局文本 | 无音乐时是否仍能稳定生成、是否保持参考身份 |
| M1 | 与M0同样数据，做无音频全局文本适配 | 性能恢复来自域适配还是时间控制 |
| M2 | M1增加分段动作与时间条件 | 是否提高逐动作完成、顺序及窗口对齐 |
| M3 | M2增加持续身份约束或一个身份适配模块 | 时间控制是否引入身份漂移，约束是否抑制运动 |
| M4 | 去掉时间信息，或交换事件顺序 | 系统是否真正使用时间条件，而非只识别动作关键词 |

先做约32个受控的人类多动作案例，2至3段事件、不同持续时间。至少包含抬手、转身、行走、坐下、拾取/放置等一般动作，并检查是否无论prompt怎样都输出舞步。保留无动作、重复事件、乱序、时间延迟、身份漂移、背景/镜头错误的失败记录。

指标以逐事件完成、顺序、时间偏差、边界连续和身份保持为主；人脸检测率/难例覆盖与静止率同时报告。32例用于可行性，不用于泛化主张；通过后扩到身份与源视频独立的128例开发集。小样本成功不能证明完整Track 2已可提交。

## 两节点执行顺序

第一周节点A建立Track 1身份专用基线；节点B按时段跑M0、素材预处理与共享评价。若M0显示原模型严重依赖音乐或无法生成普通动作，先判断需要的域适配是否超出预算，再决定继续。

第二周节点A保障Track 1可重复；节点B做M1/M2小规模条件适配。两周内若时间信息交换/删除不会改变动作安排，不能把M2当作时间控制已经接通；若出现可信收益，再把资源分配从以Track 1为主逐步调向双线。不要仅因已有舞蹈经验就先做两套大模型全量训练。

首轮可选约480p、17或33帧降低工程风险；实际时长必须与fps、事件窗口和VAE规则一致。短片段装不下2至3个完整动作时，减少事件或扩大帧数，不能靠把正常动作强行压进短视频来宣称控制成功。所有规模都需40GB实测。

## 开源桥接参考

[Wan-Dancer](https://github.com/Wan-Video/Wan-Dancer)提供图像、文本、音乐输入的全局关键帧与局部细化方案，可阅读其时间映射和连续性设计。README中的timestamp是输出文件标识，不是动作事件时间戳；作者测试硬件为8张A800 80GB，不能当作本项目8张40GB可运行保证。

[Stand-In与VACE](https://github.com/WeChatCV/Stand-In)提供身份与控制视频组合的推理路线，可作为身份/运动解耦对照。它需要实际控制素材，不能把“动作文本生成控制视频”当作已经解决；Wan2.1的组合不能自动推广为Wan2.2已验证。与直接RGB路线比较时，额外动作/姿态信息与生成成本必须计入预算。

目前没有接入具体ITA私有代码或权重，因此本文不指定实际层名、checkpoint格式、训练入口或保证迁移收益。实施前应核清基座、可用权重、条件注入位置、null音频路径、原始数据分布与输出时空规格，再编写对应adapter。
