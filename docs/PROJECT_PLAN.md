# IPVG 2027 项目执行方案

本项目以 ICASSP 2027 IPVG Track 1 的可靠提交为主目标，同时积累可独立成文的研究证据；Track 2 在主线通过验收后启动。现有规划资源为 2—4 个节点，每节点 8 张 40GB GPU。GPU 型号、互联、租期与使用单价尚未确认，因此这里的容量、时间和晋级阈值都是执行计划，不能当作已完成的 GPU 实测。

核查基准日：2026-10-17。代码仓库提供实验控制、数据清单、预算、有限自动迭代和结果记录。真实模型通过外部命令接入；本地 synthetic smoke 只验证控制流程，不代表生成视频质量、训练收敛或参赛成绩。

## 目标、交付物与先后顺序

| 优先级 | 交付物 | 完成标准 |
|---|---|---|
| P0 | 授权、数据版本与身份隔离 | 明确来源与授权；train/dev/locked-test 无身份与源视频交叉；清单可重建 |
| P0 | 一个可重复的本地视频基线 | 固定输入、配置、模型 revision 与种子，产出可播放视频及真实资源测量 |
| P0 | 有上限的自动实验循环 | 单因素假设、预算检查、超时与失败熔断、产物校验、验证集晋级和完整台账 |
| P1 | 一项有证据的方法改进 | 同预算对照、消融、多种子与独立验收集，人工抽查未发现系统性退化 |
| P1 | Track 1 primary | 官方全部输入对完整覆盖；格式与最终规则核准；至少一次全量演练 |
| P2 | Track 2 分支 | 时间线、主体类型、动作控制均能独立评价；不消耗 primary 的必要产能 |
| P2 | 论文与复现材料 | 贡献明确、来源与成本可追溯；根据实际出版 track 判断论文类别 |

不从零预训练视频基座。先把数据、推理、训练恢复和评价连成闭环，再扩大模型、数据和候选数。比较效果时严格区分“换了更强模型”“增加了采样预算”和“方法本身改进”。

## 工程主线与备用路线

1. **闭环主线：VACE 1.3B + DiffSynth-Studio。** 先采用上游公开的 VACE 条件模块训练路径；该目录中的 full 指条件模块，不自动代表整个 Wan 基座全参训练。以较小模型确认数据接线、梯度、checkpoint 导出/恢复及真实视频评价。
2. **直接身份对照：ConsisID。** 公开预处理、训练、推理和评测代码，任务形式贴近 Track 1；其上游推理显存数据不能代替训练显存测量。
3. **强推理对照：Stand-In 或 AnyID 二选一。** 先比较相同的单参考输入，不同时维护多套复杂训练栈。两者当前公开材料不足以保证官方训练流程可直接复现。
4. **模型升级：Wan2.2 I2V A14B 或 VACE 14B。** 仅在 1.3B 闭环稳定、14B 单节点资源测量通过且验证收益明确后推进。Wan2.2 的高/低噪声专家要分别记录训练与加载配置；不能把普通 I2V 当作身份模块已经接通的模型。
5. **Track 2：主体/事件状态与时间线控制。** 借鉴 ReactID 的主体条件、时间段动作条件和课程学习，但不依赖尚未核实公开的 ReactID 训练代码或权重。

具体 upstream 版本、接入检查与已有训练入口见 [UPSTREAM_INTEGRATION.md](UPSTREAM_INTEGRATION.md)。研究假设和消融见 [RESEARCH_PLAN.md](RESEARCH_PLAN.md)。

## 首个 48 小时工作窗口

计时从“服务器可用且所需数据已授权”开始，而非从写文档开始。若授权未就绪，先跑合成流程、环境探测及允许公开使用的模型样例，不把等待授权算成训练失败。

| 窗口 | 工作 | 必须留下的证据 | 退出条件 |
|---|---|---|---|
| 0—6 小时 | GPU/驱动/CPU/磁盘/互联检查；固定环境和 upstream commit；小文件资源计划 | 环境报告、磁盘余量、节点拓扑、依赖 lock 或镜像 digest | 机器资源足够且版本可追踪 |
| 6—12 小时 | 一条真实参考条件推理；构建约 32 对小开发清单 | 视频、输入清单、真实耗时、每卡峰值与错误日志 | 视频可解码；参考条件确实进入模型 |
| 12—24 小时 | 单节点 50 步训练 smoke，再扩 100—200 步 profiling | loss、非零梯度、GPU/CPU/IO、秒/optimizer step | 无 NaN/OOM；保存、恢复、导出、回载均成功 |
| 24—36 小时 | 固定小集生成与本地多维评价；人工盲查失败 | 各项指标与有效样本数、失败类型、资源总量 | 评分器识别静止/坏视频；缺失项不会变成高分 |
| 36—48 小时 | 重跑一小批与一次恢复；按实测计算周预算 | 重现报告、预算表、下一轮唯一假设 | 可重现，预算封顶，决定保留/降级/修复 |

48 小时未通过并不触发无穷重试。先降分辨率/帧数/可训练参数，或回到更小基座；把失败原因记入台账。不要为“用满所有卡”直接跨节点同步训练。

## 两节点与四节点的调度

每张 40GB 卡仍有独立容量限制。16 张卡不是一块 640GB 显存，DDP 复制基础权重，不能自动解决单进程 OOM。训练分片、序列并行及数据并行的进程组必须与 upstream 真实支持能力一致。

| 资源 | 节点分工 | 并发规则 |
|---|---|---|
| 2 节点 × 8 卡 | A：一个训练候选；B：开发集生成，结束后评价 | 不在同一未隔离 GPU 上叠训练和评价。大模型需要 8 卡时整节点独占；小模型通过 Slurm 独立分配卡 |
| 4 节点 × 8 卡 | A：训练基线；B：单因素候选；C：固定开发集生成；D：评价/预处理/机动 | 优先独立实验，不默认四节点训练同一个模型；使用 manifest/job ID 避免重复生成 |
| 最终推理 | 每节点一个已验收的 8 卡模型组，各处理不相交输入分片 | primary 优先；幂等输出与校验通过后再释放任务 |
| 跨节点训练 | 仅作为后续单独 profiling 任务 | 先测 NCCL、网络、存储和扩展效率，再比较总 GPU 小时与墙钟收益 |

服务器命令、Slurm 模板及故障处理见 [SERVER_RUNBOOK.md](SERVER_RUNBOOK.md)。

## 每周里程碑与停止条件

下表按“第 1 周”相对启动计时。若当前日期已接近 12 月，缩减研究分支，优先 primary；不得压缩必要的授权、数据隔离与全量覆盖检查。

| 阶段 | 工作与建议规模 | 晋级条件 |
|---|---|---|
| 第 1 周 | 已授权 5 千—2 万片段候选子集；32 对 smoke、128 对固定 dev；一个小模型与一个身份对照 | 清单、划分、模型版本固定；真实生成/训练吞吐与恢复通过；小集无缺失 |
| 第 2 周 | 数据筛选或身份条件的一项单因素改动；2—3 个种子 | 同预算 dev 改进；关键指标无显著退化；复跑能解释收益 |
| 第 3 周 | 选择性失败修正或 Track 2 时间线条件；不同时更换基座和评价器 | 对照采样预算/时间相等；人工盲查与 locked-test 通过；方法贡献有消融支持 |
| 第 4—6 周 | 只扩大已经有效的方法；可上 14B、加数据或开始 Track 2 | 资源增量换来稳定收益；checkpoint/导出与最终输入形式一致 |
| 12 月 9 日前 | 冻结方法、数据策略、proxy 和候选筛选规则；做 1000 对规模演练 | primary 预计用时小于可用窗口，另留至少约 25% 重跑/检查余量和上传时间 |
| 12 月 9—16 日 | 读取最终规则和测试清单；完成 primary 再考虑其他 run | 无漏项/坏片/配置漂移；最终 run 可追踪；本人核准后提交 |
| 12 月 22 日后 | 结果分析、失败归因、论文消融与复现整理 | 不把最终测试反馈伪装成预先验证；论文资格与出版类别已确认 |

建议第一次探索额度为 **300—800 GPU 小时**，通过 48 小时门槛后据实分配；这是可调整的预算上限，不是收敛保证。每周继续投入前检查：有效模型比例、失败率、最佳候选的同预算收益、剩余资源、primary 能否按时完成。

停止或回退的触发包括：连续失败超过配置阈值、预算即将耗尽、评价/清单版本漂移、train/dev/locked-test 交叉、候选收益只来自更多采样、人工抽查发现身份分数靠静态视频提高。具体自动上限以 campaign 配置为准。

## 风险与责任

| 事项 | 当前状态 | 决策 |
|---|---|---|
| 官方完整 scorer、权重与实时榜 | 尚未公开核实 | 本地指标明确称 proxy，保留人工抽检 |
| 预训练模型、外部数据、best-of-N、测试时微调 | 公开规则未完整说明 | 先完成方案和本地实验；正式测试前核准允许范围 |
| 数据协议与账号操作 | 需本人授权/真实签名 | 不代签，不把受限素材推入 GitHub 或外部 API |
| 40GB GPU 适配 | 尚未实测 | 每个模型从小配置开始，保存峰值与吞吐证据 |
| 论文发表 | 有日期但资格/出版细则待核 | ICASSP 属 CCF B 不代表 challenge 报告自动是 B 类 Full/Regular |
