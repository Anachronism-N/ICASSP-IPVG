## 二、已识别的数据质量问题

### 1. MIRA

旧版本 43,800 条样本的审计结果：75.3% 时间字段为 `0 -> 0`、100% `arena=Unknown`、全部缺少 `caption_i2v`，平均详细 caption 约 757 字符。该版本已经被隔离为 `mira_captions_manifest_old_bad.jsonl`。

最终版本前 10,000 条抽样结果：

| 指标 | 结果 |
|---|---:|
| `caption_i2v` 缺失 | 0 |
| `arena=Unknown` | 0 |
| `caption_i2v` 平均长度 | 86.2 字符 |
| caption 超过 240 字符 | 0 |
| 时间仍为 `0 -> 0` | 75.7% |

结论：最终版短 caption 已明显改善，可用于 pilot；结构化时间仍有系统性错误。在修复时间解析前，不应使用该字段做事件切片、时序条件或质量评分。

### 2. Charades

当前 `training_metadata/charades_metadata.csv` 的 prompt 基本为同一泛化句子加 video ID，没有描述真实动作。不能直接作为训练 caption。

处理顺序：先解析官方 action label 生成动作句，再由 VLM 补充人物、物体、动作顺序、镜头和结果。video ID 不应进入 prompt。

### 3. HOIGen

已有 caption 较长，部分内容可能更像静态场景描述。首轮需要进行长度、动作词、结果状态和重复度过滤，优先保留明确的手物交互、动作变化和动作结果。

### 4. Seamless Interaction

Transcript 描述说话内容，但不一定描述画面动作。首轮可保留全部 476 条，同时增加简短 visual caption；训练字段建议组合为“可视动作 + 对话语义”，避免只学到字幕文本。

## 三、执行原则

1. 不等待 MIRA 2M 全量进入训练，先从高质量子集跑通闭环。
2. 不全量解压 OpenVidHD 和 Matrix；先索引 ZIP 中央目录，再按需抽取。
3. 不在确认 DiffSynth 数据加载规格前继续大规模固定分辨率转码。
4. 训练集、验证集按 `source_sequence_id` 或原视频 ID 切分，禁止相邻 clip 随机泄漏。
5. TI2V 必须验证首帧条件是否由数据加载器正确生成；不能只相信配置文件描述。
6. Qwen3-VL caption 和 Wan2.2 训练共享 8x H20，采用“小批量 caption -> 关闭 vLLM -> smoke training”的交替调度。
7. 下载任务不作为首轮训练的前置依赖。

## 四、24 小时执行计划

| 时段 | 任务 | 输出 | 验收门槛 |
|---|---|---|---|
| 0-2h | 修复训练前置环境 | Wan 权重、accelerate 环境、模型文件清单 | 权重完整，训练脚本 `--help` 可运行 |
| 0-4h | Caption DexYCB 2,400 + H2O 60 | 两份 metadata CSV | 路径 100% 存在，caption 描述真实动作 |

| 2-6h | 建立统一 manifest v1 | 20K-50K train/val CSV | 无路径错误、无跨 split 源泄漏 |
| 4-8h | 视频/首帧预检 | 解码报告、首帧检查 | 随机 500 条全部可解码 |

## 五、首轮数据配比

| 来源 | 建议数量 | 目的 |
|---|---:|---|
| HOIGen-1M | 10K-20K | 人物、手物和日常交互主体 |
| MIRA final | 5K-10K | 高动态运动和第一视角控制 |
| DexYCB | 2,400 | 精细手物交互，全量纳入 |
| H2O | 60 | 第一视角手物操作，全量纳入 |
| Seamless Interaction | 476 | 多人对话和互动，全量纳入 |
| Charades | 3K-5K | 日常活动和动作组合 |
| OpenVidHD pilot | 0-5K | 仅在原生 caption/筛选完成后补充多样性 |

单一来源占比建议不超过 50%。MIRA 和 HOIGen 都必须按源序列去重，避免大量相邻片段主导训练。

## 六、统一训练字段与 Caption 规范

最低字段：

```json
{
  "video": "relative/path/to/video.mp4",
  "prompt": "A person picks up a cup, pours water into it, and places it on the table.",
  "source_dataset": "dataset_name",
  "source_sequence_id": "stable_source_id",
  "split": "train",
  "fps": 24,
  "num_frames": 49
}
```

Caption 要求：

- 使用自然英文，通常 1-3 句，优先动作、交互对象、动作顺序和可见结果。
- 明确镜头运动或第一/第三人称视角，但只描述画面可验证内容。
- 不写 video ID、文件名、内部坐标、不可见控制键和无意义精确速度。
- 避免固定开头和大段场景堆砌。
- 对 I2V，描述首帧之后发生的变化，减少对首帧静态内容的重复。

## 七、Smoke Training 前置检查

当前 `scripts/smoke_test_wan22.sh` 不能直接视为快速 smoke：5,476 样本乘以 `dataset_repeat=10`，规模仍然过大。应先生成 64-256 条独立 smoke metadata，并将目标控制在 100-500 steps。

启动前检查：

- Wan2.2 模型权重文件存在且大小合理。
- `accelerate`、PyTorch、DiffSynth 依赖可导入。
- 训练 metadata 中的每个视频路径都能解析。
- 至少随机验证 500 个视频可被 FFmpeg 解码。
- 49 帧采样策略对短视频不会产生空帧或越界。
- 首帧确实作为 `input_image` 传入，而不是只训练 T2V。
- 关闭未配置的 W&B；当前 `train_wan22.sh` 会无条件传入 `--enable_wandb_log`。
- 首次只保存一个短 checkpoint，并验证可恢复和可推理。

当前预期启动入口：

```bash
bash scripts/smoke_test_wan22.sh
```

在上述检查完成前不要直接运行全量 `scripts/train_wan22.sh`。

## 八、大数据集处理策略

### OpenVidHD

1. 先检查发布方是否附带原生 caption/metadata，避免对 300K+ 视频重复 VLM 标注。
2. 扫描 ZIP 中央目录，建立 member、压缩大小、来源 part 的索引。
3. 从 81 parts 分层采样 10K，进行时长、分辨率、黑帧、重复和水印过滤。
4. 第一轮只抽取 10K；质量通过后扩展到 50K。
5. 不产生“4TB 压缩包 + 全量解压副本 + 全量转码副本”的三份存储。

### Matrix

1. 对 122 个 ZIP 进行 CRC/中央目录检查。
2. 按游戏、镜头类型、运动强度和场景分层抽取 5K-10K。
3. MIRA 已提供大量 Rocket League 内容，因此 Matrix 的优先级低于真实人物交互数据。
4. 只有首轮模型证明缺少驾驶、第三人称或复杂运动后才扩大。

### Inter-X

16.9GB 是否足够不能只看体积。先确认文件清单、序列数、动作类别、主体数量和是否包含 RGB 视频。若只有骨骼、SMPL 或动作参数，则不能直接用于 Wan2.2 像素级 TI2V；可保留为后续姿态条件、动作控制或渲染增强数据。

## 九、资源调度

建议 GPU 时间片：

1. 启动 Qwen3-VL，仅处理 DexYCB、H2O、Charades pilot 和最多 1K OpenVidHD。
2. Caption 完成后关闭 vLLM，释放全部 GPU。
3. 运行 Wan2.2 64-256 样本 smoke training。
4. 通过 loss、checkpoint 和推理验收后，扩到 20K-50K。
5. 训练稳定期间再安排下一批 VLM caption，不让 OpenVidHD 全量标注连续阻塞训练。

CPU/存储任务可并行执行：ZIP 建索引、metadata 转换、重复检测、split 生成和 FFmpeg 解码审计。

## 十一、验收标准

### 数据验收

- metadata 路径存在率 100%。
- 随机 500 条视频解码成功率 100%。
- 空 caption 为 0；重复 caption 和模板化 caption 有统计。
- train/val 按源序列隔离，跨 split 源泄漏为 0。
- 每个来源的样本数、时长、分辨率和占比有报告。

### 训练验收

- 100-500 steps 无 OOM、NaN 或持续数据加载失败。
- checkpoint 能保存、加载并继续训练。
- 固定 prompt 和固定首帧可生成对照视频。
- LoRA 相比基座在目标动作上有可见改善，且首帧主体和场景保持稳定。
- 通过 smoke 后再进入 20K-50K 首轮训练，首轮通过后才扩大 OpenVidHD、Matrix 和 MIRA。

## 十二、明确的下一步

1. 把所有 MIRA 下游输入从空的 `mira_captions_manifest.jsonl` 改为 `mira_captions_final.jsonl`。
2. 下载并校验 Wan2.2-TI2V-5B 权重，建立包含 `accelerate` 的可复现训练环境。
3. 生成 64-256 条真正的 smoke metadata，修正 W&B 和 repeat 配置。
4. 给 DexYCB、H2O 打 caption，同时生成 MIRA 5K-10K 质检子集。
5. 合并 20K-50K unified manifest，按源序列切分。
6. 完成首帧、解码和字段审计后启动 smoke training。
7. Smoke 通过后启动首轮 LoRA；OpenVidHD 和 Matrix 继续做索引和抽样，不全量解压。
