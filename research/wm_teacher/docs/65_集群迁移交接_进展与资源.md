## 2. 训练实验细节（docs/64 之后的新内容）

### T2b（train_T2_dpo002）
- 设置与 T2 相同（158 对、β 100、120 步、全局 batch 8），只把 lr 从 2e-5 改为 1e-4。
- 训练对上隐式准确率 0.64 → 0.79，DPO 间隔 0.04 → 1.85，说明策略真的动了。
- 开发集结果（候选 − base，seed0 / seed1）：
  - Total* −9.61 / −9.07pp
  - dynamic −16.0 / −13.8pp
  - subject_consistency −13.0 / −13.3pp
  - imaging −18.6 / −18.8pp
  - DreamSim +0.109 / +0.111
  - 运动误差 −0.09（变好）
  - 护栏 smooth、subject、DreamSim 三项都没过。
- 结论：这组奖励（V-JEPA2 惊讶度 + VideoReward MQ，外加运动下限 0.8）在偏好对上可以被拟合，但拟合的方向是更静、更糊的视频。两项奖励与运动量的相关分别是 −0.24 和 −0.31，同组去均值后仍为 −0.12 和 −0.14。**这组奖励不能直接用于 DPO。**

## 5. 已知问题与教训（换集群后仍然适用）

1. **节点主机名无法解析**：单机 torchrun 必须加 `--local-addr 127.0.0.1`；多机时 `--local-addr` 用本机 IP，并设 `NCCL_SOCKET_IFNAME` / `GLOO_SOCKET_IFNAME`（旧集群是 bond1，`NCCL_IB_DISABLE=1` 沿用用户原有配置；新集群要按实际网卡改）。
2. **共享盘随机读会卡死**：在旧集群上读一个 10MB 文件要 48–450 秒，而顺序大块写约 55–73MB/s。**训练前必须先把缓存放到本地盘**（scripts/copy_cache_local.py 按索引复制，不扫目录）；训练输出也应先写本地盘。
3. **训练时长规格**：按实测步时（26–29 秒/步，8 卡，offload off，峰值约 28.6GB/卡）乘以 1.3 再给上限；正式训练一律加 `--save-partial-on-budget-stop`。
4. **计费规则**：每个运行按上限计，失败不退。台账已经因为基础设施问题多计了约 160 GPUh。
5. **占卡协调**：旧集群上用户的 hold_gpu.py 和 watchdog 协议（/tmp/od_reserve_N、/tmp/ms12k_gpu_N.lock、PIDFD 精确 TERM）是旧集群特有的，新集群需要重新确认有没有占卡进程。
6. **奖励偏差**：V-JEPA2 惊讶度和 VideoReward MQ 都偏好静止的视频，用 DPO 直接优化会塌缩（T2b）。必须加入与真实视频运动的约束，或者用 KL 更强、在线的方法（NFT），并且先在开发集上小规模验证。
7. **009b 标签的系统性问题**：慢速运动被抹掉、手与物体的交互被写扁平、相机运动有漏标。
