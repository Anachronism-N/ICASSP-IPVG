## 一、Wan2.2-TI2V 训练格式要求

### 1.1 模型实际行为（源码验证）

基于对 DiffSynth-Studio 源码的核查（`operators.py:157-195`、`unified_dataset.py`），Wan2.2-TI2V 训练时的**实际**数据加载行为：

| 维度 | 实际行为 | 影响 |
|------|---------|------|
| 帧采样 | 从 **frame 0 开始取 49 个连续帧**，无间隔采样 | 只用视频前 ~2s |
| 起始位置 | **固定 frame 0，无随机偏移** | 每个 epoch 看到相同片段，长视频后半段浪费 |
| 帧数约束 | `N % 4 == 1`；视频 < 49 帧时自动降帧，不报错 | 短视频能跑但帧数减少 |
| 分辨率处理 | "cover" 缩放 + center crop，**无 bucket 分桶** | 竖屏视频放入横屏目标会裁掉大部分画面 |
| 默认 Wan2.2 脚本 | `--height 480 --width 832 --num_frames 49`（固定尺寸） | 本项目改用 1280×704 |

**关键结论**：
- 49 帧 / 24fps = **~2.04 秒**，数据加载器只用视频的前 2 秒
- 视频时长 > 2s 的部分**不会被使用**（无随机起始帧）
- 视频时长 < 2.04s（49 帧）时自动降帧到满足 `N % 4 == 1` 的最大值（48→45, 30→29, 20→17）
- 竖屏视频（1080×1920）不能与横屏（1280×704）混入同一固定尺寸 batch

### 1.2 格式要求

| 维度 | 要求 | 说明 |
|------|------|------|
| 容器 | MP4（H.264） | DiffSynth-Studio 数据加载器默认 |
| 分辨率 | 1280×704（横屏）或 704×1280（竖屏） | 16:9.3，宽高必须被 16 整除 |
| 帧率 | 24 fps | 训练配置 `--num_frames 49`（~2s） |
| 时长 | **2-5 秒，无需切分；>5s 切分为 4s 段** | 见下方切分策略 |
| 帧数 | ≥49 帧（≥2.04s）最佳；不足自动降帧 | |
| 首帧 | 自动提取为 `input_image` | TI2V 条件输入 |
| Caption | 自然英文，1-3 句 | 可后续补充；首次可空 |

### 1.3 切分策略

基于"只用前 49 帧（~2s）"的源码行为：

| 原始时长 | 处理方式 | 原因 |
|----------|---------|------|
| **2-5s** | **不切分，直接使用** | 只用前 2s，5s 也只浪费 3s，可接受 |
| **>5s** | 切分为 **4s 段** | 4s = 96 帧，取前 49 帧只浪费 47 帧（~49%），平衡利用率和段数 |
| **<2s** | 不切分，自动降帧 | 数据加载器自动处理，但时序质量受损 |
| **<1s** | 排除 | 帧数太少，降帧后质量差 |

**段长选择依据**：
- 不选 2s（49 帧）：刚好等于采样窗口，无缓冲，边界视频可能差 1-2 帧导致降帧
- 不选 8s：只用前 2s，浪费 75%
- **选 4s**：96 帧，取前 49 帧，浪费 49%，每段仍能提供完整的 49 帧训练窗口

### 1.4 分辨率分桶策略

数据加载器无内置 bucket 分桶，使用 "cover" resize + center crop：

| 桶 | 分辨率 | 适用数据集 | 首轮是否使用 |
|----|--------|-----------|------------|
| 横屏 | 1280×704 | MIRA, Charades, DexYCB, EasyCom, H2O, NoXi, Matrix | ✅ 是 |
| 横屏微调 | 1280×720 → 1280×704 | HOIGen（pad 16px） | ✅ 是 |
| 竖屏 | 704×1280 | Seamless, OpenVidHD | ❌ 后续阶段 |

**首轮训练**：仅使用横屏数据（1280×704），避免竖屏 center crop 丢内容。竖屏数据后续单独跑一桶或改用动态分辨率模式（`--max_pixels`）。

## 三、处理流水线设计

### 3.1 流水线阶段

```
原始数据 (zip/tar/原始MP4)
  │
  ├─ [阶段1] 提取：从压缩包中提取 MP4
  │
  ├─ [阶段2] 转码：统一到 1280×704/24fps（横屏桶）或 704×1280/24fps（竖屏桶）
  │
  ├─ [阶段3] 切分：长视频按 4-8s 切分为短段
  │
  ├─ [阶段4] 质检：解码验证、首帧提取、时长/分辨率校验
  │
  ├─ [阶段5] Caption：VLM 打标或模板生成（可后续补充）
  │
  ├─ [阶段6] 筛选：按 caption 质量/标签/时长/分辨率筛选（后续）
  │
  └─ [阶段7] Manifest：生成 DiffSynth CSV (video, prompt)
```

### 3.2 转码命令模板

```bash
# 横屏桶：任意分辨率 → 1280×704, 24fps, h264
ffmpeg -i input.mp4 \
  -vf "scale=1280:704:force_original_aspect_ratio=decrease,pad=1280:704:(ow-iw)/2:(oh-ih)/2" \
  -r 24 -c:v libx264 -preset fast -crf 18 -an -y output.mp4

# 竖屏桶：任意分辨率 → 704×1280, 24fps, h264
ffmpeg -i input.mp4 \
  -vf "scale=704:1280:force_original_aspect_ratio=decrease,pad=704:1280:(ow-iw)/2:(oh-ih)/2" \
  -r 24 -c:v libx264 -preset fast -crf 18 -an -y output.mp4
```

### 3.3 切分策略

| 数据集 | 原时长 | 目标段长 | 切分方式 |
|--------|--------|---------|---------|
| Charades | 30-46s | 6-8s | 均匀切分（无动作边界标注） |
| EasyCom | 60s | 6-8s | 均匀切分 |
| H2O | 15-17s | 6-8s | 均匀切分 |
| NoXi | 900-1168s | 6-8s | 按 VAD 边界切分（优先），否则均匀 |
| Seamless | 166-222s | 6-8s | 按 VAD/对话边界切分 |
| Matrix | 14s | 6-8s | 均匀切分（可能 2 段） |

切分命令模板：
```bash
# 按 8s 均匀切分
ffmpeg -i input.mp4 -c copy -map 0 -f segment -segment_time 8 -reset_timestamps 1 output_%03d.mp4
```

### 3.4 分辨率分桶训练策略

**首轮训练**：仅使用横屏桶（1280×704），避免 batch 内尺寸混用。
- 可直接使用：MIRA, DexYCB, Charades（切分后）, EasyCom（切分后）, H2O（切分后）, NoXi（切分后）, Matrix（转码+切分后）
- HOIGen：1280×720 → 1280×704（pad 16px），可纳入横屏桶

**后续阶段**：加入竖屏桶（704×1280）——Seamless, OpenVidHD。需在 DiffSynth 数据加载器中支持按桶分组采样。

## 五、数据筛选策略（后续阶段）

在 caption 和标签就绪后，按以下维度筛选训练数据：

### 5.1 按 Caption 质量筛选

- **长度过滤**：保留 40-200 字符的 caption；过短（<20）信息量不足，过长（>500）偏静态描述
- **模板化检测**：MIRA 的 `caption_i2v` 有固定句式（"A Rocket League player ... from X team perspective."），需统计重复率，过高则降采样
- **动作词覆盖**：确保 caption 包含明确动作动词（pick up, pour, turn, open, push 等），排除纯场景描述
- **结果状态**：优先保留描述动作结果的（"and places it on the table"），而非仅描述开始

### 5.2 按原始标签筛选

| 数据集 | 可用标签 | 筛选维度 |
|--------|---------|---------|
| MIRA | `actions.dominant_actions`, `physics.airborne_frames`, `physics.has_jumped` | 按动作复杂度筛选，排除 idle_pct 过高的段 |
| HOIGen-1M | CSV 自带 action label | 按人-物交互类型筛选 |
| Charades | `action_classes`（157 类） | 按动作类别平衡采样 |
| DexYCB | `object`（20 类 YCB 物体） | 按物体类别平衡 |
| Seamless | VAD 标签 | 排除纯静默段 |

### 5.3 按视频质量筛选

- **时长**：2-10s（切分后需重新校验）
- **分辨率**：≥480p 原始分辨率
- **黑帧/重复帧**：FFmpeg 检测黑帧，排除
- **水印**：OpenVidHD/YouTube 来源可能有水印，需检测
- **运动模糊**：光流方差过低的段排除

### 5.4 按训练目标筛选

- **首轮**：优先保留明确动作变化、手物交互、人物交互的段
- **排除**：纯静态场景、纯黑/纯白、文字/幻灯片为主的段
- **平衡**：单一来源占比 ≤50%，按来源、动作类型、视角分桶平衡
